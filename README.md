# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

> 한국폴리텍대학 강서캠퍼스 사이버보안과 실습 프로젝트  
> Google Antigravity IDE & Open-Meteo 공개 기상 데이터 API 연동

---

## 🌤️ 소개

**실시간 날씨 & 미세먼지 스마트 대시보드**는 전 세계 오픈 기상 데이터(Open-Meteo)를 활용하여 대한민국 주요 도시 및 전 세계 도시의 기상 상태와 대기 환경을 실시간으로 시각화하는 React 웹 애플리케이션입니다.

- **주요 도시 원클릭 조회**: 서울(강서), 서울(시청), 인천, 부산, 대구, 대전, 광주, 제주 등 8개 주요 도시 빠른 선택
- **실시간 날씨 카드**: 기온, 체감온도, 상대습도, 풍속, 강수량 및 WMO 코드 기반 Lucide 날씨 아이콘/한글 라벨 표시
- **미세먼지(대기질) 지수**: PM10, PM2.5 측정 수치 및 한국 환경부 기준 4단계(좋음/보통/나쁨/매우 나쁨) 컬러 뱃지 & 행동 요령 안내
- **24시간 시간별 기온 차트**: `hourly` 기상 데이터를 연동한 순수 SVG 꺾은선 + 그라디언트 채우기 미니 차트 (가로 스크롤 지원)
- **향후 7일간 주간 예보**: `daily` 데이터를 활용한 요일별 날씨 아이콘, 강수 확률(%), 최고/최저 기온 범위 바(Bar) 시각화
- **스마트 도시 검색창**: 400ms 디바운스(Debounce)가 적용된 전 세계 도시 검색 및 자동완성 드롭다운

## 🤖 어떻게 만들었나요 (Antigravity IDE 경험)

- **선 계획 수립(Implementation Plan) 중심 개발**:  
  단순히 코드를 자동 완성하던 이전의 AI 어시스턴트(Copilot)와 달리, Antigravity IDE는 코드를 바로 작성하지 않고 **요구사항 분석 → 아키텍처 설계 → 검증 계획**을 담은 `Implementation Plan`을 먼저 제시하여 개발자가 검토 및 승인(`Proceed`)한 뒤 안전하게 코드를 반영하는 성숙한 엔지니어링 워크플로우를 체감했습니다.
- **점진적 2단계 빌드업과 모듈화**:  
  Vite 기본 화면에서 출발하여 1단계(핵심 API 연동 및 기본 카드 구축) → 2단계(컴포넌트 분리 모듈화 및 차트/예보/검색 고도화)로 차근차근 확장해 나가는 과정이 매우 체계적이었습니다.
- **자율 검증 및 Walkthrough 리포트**:  
  코드 작성이 끝난 후 에이전트가 터미널 빌드(`npm run build`)를 스스로 수행하여 문법 오류와 번들링 상태를 검증하고, 상세 결과 리포트(Walkthrough)를 자동으로 제공하여 신뢰성을 높였습니다.
- **Git 커밋 자동 위임 (Rules 기반)**:  
  `GEMINI.md` 프로젝트 규칙에 정의된 표준 커밋 규격(한국어, 50자 요약 제목, 불릿포인트 상세 목록, `Co-authored-by` 서명)에 따라 Chat에서 커밋을 지시하기만 해도 일관성 있는 고품질 커밋이 자동으로 생성되는 편리함을 경험했습니다.

## 📡 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- **Open-Meteo 공개 API의 특징**:  
  별도의 회원가입이나 API Key 발급 없이 HTTPS 프로토콜을 통해 실시간 날씨(`forecast`), 미세먼지(`air-quality`), 도시 검색(`geocoding`) 데이터를 비상업적 목적 기준 하루 최대 10,000회까지 완전 무료로 제공합니다.
- **UI 컴포넌트와 API 통신 레이어의 철저한 분리 (Decoupling)**:  
  `src/api/weather.js` 모듈에 네트워크 호출(`fetchWeatherData`, `fetchAirQualityData`, `searchCities`) 및 WMO 코드 한글 매핑(`getWeatherInfo`), 환경부 기준 등급 산출(`getAirQualityStatus`) 로직을 격리하였습니다. 이를 통해 UI 컴포넌트는 오직 화면 렌더링에만 집중할 수 있으며, 향후 API 엔드포인트나 데이터 스키마가 변경되어도 UI 코드 수정 없이 통신 모듈만 유지보수할 수 있습니다.
- **디바운스(Debounce)를 적용한 도시 검색**:  
  사용자가 키보드로 도시명을 입력할 때 매 타이핑마다 즉시 API를 호출하면 초당 수십 회의 불필요한 HTTP 트래픽이 발생합니다. `CitySearch.jsx`에 **400ms 디바운스 타이머**를 적용하여, 사용자의 입력이 멈춘 후 400ms 뒤에 단 한 번만 요청하도록 제어함으로써 클라이언트 자원 절약 및 서버 DoS 부하를 방지했습니다.

## 🛡️ 보안에서 확인한 것 (사이버보안과 체크포인트)

1. **Public API vs Private/Secret API (키 분리와 백엔드 프록시의 필요성)**:  
   Open-Meteo는 키가 없는 공개 API이므로 프론트엔드에서 직접 호출해도 안전하지만, **비밀 키(`secret key`)나 유료 결제 모듈이 필요한 API는 절대 React 프론트엔드 코드에 키를 넣어서는 안 됩니다.** 브라우저의 개발자 도구(F12) Network 탭이나 배포된 번들 JS 파일에서 키가 100% 노출되어 비인가 호출, 데이터 유출, 과도한 금전적 과금 피해로 이어집니다.  
   따라서 민감한 API를 다룰 때는 프론트엔드가 자체 백엔드(BFF, Backend For Frontend)를 호출하고, 서버 환경변수(`process.env`)에 비밀 키를 숨겨 외부와 통신하도록 설계해야 합니다.
2. **Rate Limit과 DoS/429 차단 방어**:  
   인증 키가 없는 공개 API는 클라이언트의 **IP 주소를 기반으로 요청 빈도를 감시**합니다. 디바운스 없이 무작위로 호출을 남발할 경우 API 방화벽에 의해 **HTTP `429 Too Many Requests`** 에러와 함께 IP가 일시적 또는 영구적으로 블랙리스트 차단될 수 있습니다.
3. **CORS와 Mixed Content (HTTPS 암호화)**:  
   배포된 웹 애플리케이션이 `https://` 보안 프로토콜 상에서 동작할 때, 평문 프로토콜인 `http://` API 엔드포인트를 호출하면 브라우저의 동일 출처 및 혼합 콘텐츠(Mixed Content) 차단 정책에 의해 통신이 강제 차단됩니다. Open-Meteo의 모든 API 엔드포인트는 종단 간 암호화(TLS/HTTPS)를 기본 제공하므로 중간자 공격(MITM) 및 도청 위험을 방지합니다.

## 🎨 커스터마이징한 부분

실습 6단계 커스터마이징 챌린지 및 추가 사용자 경험 고도화를 진행했습니다:

1. **라이트 / 다크 모드 수동 전환 (기본: 라이트 모드)**:
   - 상단 헤더에 `Sun` / `Moon` 테마 전환 버튼 탑재
   - `localStorage`를 활용하여 사용자가 선택한 테마 모드를 영구 보존
   - 다크 모드와 라이트 모드 각각에 맞춘 세련된 카드 글래스모피즘(`backdrop-filter: blur(16px)`) 및 명도/대비 최적화
2. **실시간 기상 상태 연동 감성 배경 이미지 & 맞춤 그라데이션**:
   - `weatherData.current.is_day`(낮/밤)와 `weather_code`를 실시간 분석
   - 맑음(낮/밤), 흐림(구름), 비(소나기), 눈(설경), 안개, 뇌우 등 날씨에 따라 어울리는 고화질 감성 비주얼 배경과 반투명 그라데이션 오버레이를 자동 블렌딩
   - 도시 변경이나 날씨 변화 시 `transition: background 0.8s ease`로 자연스럽게 전환
3. **섭씨(°C) ↔ 화씨(°F) 원클릭 단위 전환 토글**:
   - 상단 헤더에 단위 전환 스위치 버튼 배치
   - 토글 클릭 시 현재 기온, 체감온도, 24시간 시간별 기온 차트, 7일간 주간 예보의 기온 수치를 일괄 변환 및 즉시 동기화
